## Operator workflow

Counts are authorized, payment-mode-scoped backend data across all matching records; recent list/search is explicitly limited to latest100. No unread claims. Inquiry and awaiting agreement are one current lifecycle state, not fabricated separate stages. Notification pending remains an attention condition. Verified live paid totals require live binding and checked paid status; test/legacy, unpaid, refunded and disputed records excluded. This is a current paid snapshot, not net accounting or recognized revenue. Historical records have no new required data or migration.

Bookings are one active record within each engagement, not another calendar. Date/time entry is explicitly UTC with an IANA display zone; confirm converted time with the provider. Free discovery may precede scope approval/payment. Paid-session confirmation retrieves Stripe state and requires paid approval. Cancellation/rescheduling clears the confirmed time; reference can retain context. Dates/zones/HTTPS meeting links validated on server. Follow-up controls cannot independently change booking state. There is no automatic availability check, provider synchronization, reminder or invitation; provider is authoritative for conflicts. A repeated save updates the same engagement, not a new booking.
